# RuleTrace Scholar 研究定位与实施路线

## 1 项目结论

这个项目不应继续定位为另一个“上传 PDF 后聊天”的 ScholarRAG，也不应仅复制外部论文搜索、报告生成和矛盾检测。新的核心定位是：

> RuleTrace Scholar 是一个面向科研问答的可解释智能体 RAG 系统。它把回答拆成可核查声明，将声明连接到检索证据，并通过公开的动态规则计算证据可靠性、风险等级和补证路径。

这里的“可解释”限定为**证据路径可解释性**和**过程忠实性**。系统不宣称黑箱 LLM 本身已经变成可解释模型，也不把启发式可靠性分数伪装成真实概率。

## 2 两个参考项目的边界

| 维度 | ScholarRAG | Personal Research Assistant Agent | RuleTrace Scholar |
|---|---|---|---|
| 核心任务 | 本地论文问答 | 外部检索与研究报告 | 可审计科研问答与证据诊断 |
| 检索 | BM25 加稠密检索 加重排 | Chroma 相似度 加 MMR 加重排 | 混合检索 加重排 加元数据感知证据多样性 |
| 文档理解 | Docling 结构化解析和 VLM | PyMuPDF 文本抽取 | 保留结构化解析与 VLM |
| 多智能体 | LangGraph 分解 反思 综合 | ReAct 工具循环 | LangGraph 加 TRACE 证据策略层 |
| 引用 | 文献 章节 页码 | 标题 URL | 声明级引用边与证据摘录 |
| 可靠性 | RAGAS 离线评价 | LLM 生成总体置信度 | 可复算规则 加风险决策 加未校准边界 |
| 矛盾 | 综合提示中处理 | LLM 对摘要做矛盾检测 | 对声明绑定的原文摘录执行结构化蕴含与冲突审计 |
| 可解释性 | 来源列表 | 日志和报告 | 声明证据图 规则激活 反事实补证 |

第二个参考项目的外部检索、MMR、报告、历史记录和矛盾面板适合成为后续工作流层。但它的矛盾检测主要比较摘要并由 LLM 自报结果，无法保证每个冲突都绑定可核查段落；它的报告置信度同样缺少可复算定义。因此，这些功能不能替代我们的研究核心。

## 3 两篇论文到通用科研 RAG 的迁移

### 3.1 从 AgriRule LLM 迁移的思想

原论文的重要点不是农业变量本身，而是以下方法论：

- LLM 只负责提出候选构造，不直接决定最终预测或规则。
- 候选必须经过可用性、泄漏、跨样本依赖和特征增长审计。
- 选择目标同时考虑性能、稳定性与规则紧凑性。
- 动态数据先转成适合规则学习的表示，再进入规则模型。

在 RuleTrace Scholar 中，对应关系如下：

| 论文概念 | 系统转化 |
|---|---|
| 候选特征程序 | 查询分解与候选证据路径 |
| 预测时可用性 | 回答时实际检索到的证据，不允许事后补写出处 |
| 泄漏审计 | 无效引用、越界引用、会话跨路由缓存隔离 |
| 规则紧凑性 | 五条核心证据规则和简洁激活轨迹 |
| 稳定性 | 后续通过查询扰动和重复运行评估规则结果稳定性 |

### 3.2 从 AgriDRN 迁移的思想

原论文强调动态阈值、层次逻辑、规则可靠性与不确定性，并强调同一规则激活路径服务预测与解释。通用化之后：

| 论文概念 | 系统转化 |
|---|---|
| 动态二值化阈值 | 按问题类型和问题复杂度调整证据阈值 |
| 层次逻辑规则 | 声明层指标到回答层可靠性决策 |
| 规则支持度 | 每条声明的来源数量与来源独立性 |
| 异方差不确定性 | 未校准证据不确定性指数和风险等级 |
| 共享规则路径 | 同一批检索引用同时进入回答和 TRACE 报告 |
| 代表性规则导出 | UI 展示实际激活规则、阈值和观测值 |

论文也明确指出高覆盖区间仍可能欠校准。因此本项目必须把当前分数称为“证据质量指数”，在完成带人工标签的校准实验之前，不能称为正确率概率或置信概率。

## 4 已实现的 TRACE 技术层

TRACE 表示 Transparent Rule based Attribution and Citation Evidence。

### 4.1 声明证据图

系统把最终回答切分为声明节点，并解析每个声明后的引用编号。有效编号连接到证据节点，证据节点保留文献、章节、页码、块标识、节点类型、检索相关性和摘录。

### 4.2 动态规则

- R1 Claim grounding：需要证据的声明是否都有有效引用。
- R2 Citation validity：引用编号是否都能映射到真实检索结果。
- R3 Source traceability：来源是否同时具有文献和位置元数据。
- R4 Evidence diversity：证据是否来自独立论文或章节，而不是重复块。
- R5 Evidence density：复杂或定量声明是否具有足够证据密度。

实验结果类问题使用最严格阈值；方法类次之；背景类相对宽松。子问题越多，覆盖、多样性和发布阈值越高。

### 4.3 可靠性与证据门控

规则通过加权透明公式形成可靠性分数，并输出 supported、caution 或 insufficient。若启用证据门控，insufficient 回答会附加明确警告。所有规则的表达式、观测值、阈值和通过状态均返回前端。

### 4.4 反事实补证

失败规则直接生成下一步动作，例如：为未引用声明重新检索、修复越界引用、补充独立论文、为定量声明增加第二证据。这种建议来自规则差距，不是 LLM 随机生成的解释文本。

## 5 已完成增强与下一阶段研究

### 阶段 A 当前版本

- 完成声明证据图、动态规则、证据门控、反事实建议与可视化。
- 修复引用对象缺少证据摘录和 VLM 元数据的问题。
- 为 CrossEncoder 相关性增加可显示归一化值。
- 增加元数据感知的证据多样性选择。

### 阶段 B 当前已实现

- 用结构化模型输出判断声明与证据之间的支持、不足和矛盾，并把模型判断明确标为辅助审计而非事实证明。
- 检测引用摘录之间的 contradiction / tension 关系并绑定证据编号。
- 对部分未落地声明执行一次有界“检索—重写—TRACE 复验”，只有可靠性等级或分数改善才采纳。
- 并发连接 arXiv、Semantic Scholar 与 Crossref；单源限流时自动降级，可信 arXiv 标识可一键导入全文。
- 将规则、确定性测试与语义审计合成为 supported / review / blocked 发布决策。

### 阶段 C 可投稿增强

- 构建跨论文立场图，只有共享同一研究问题、数据集和指标的证据才形成可比较冲突边。
- 对同一查询做语义扰动，测量声明、证据和规则激活稳定性。
- 引入时间、论文质量和撤稿状态等来源先验，但保持每项权重公开。

### 阶段 D 校准与用户研究

- 建立人工标注集，包括声明支持性、引用正确性、冲突真实性和回答可用性。
- 用温度缩放或等距回归校准可靠性分数，并报告 ECE、Brier score 和风险覆盖曲线。
- 与无解释 ScholarRAG、只显示引用、LLM 自解释、LLM 自报置信度进行消融比较。
- 开展用户研究，测量错误识别率、核查时间、过度信任和认知负担。

## 6 建议实验矩阵

| 研究问题 | 对照 | 指标 |
|---|---|---|
| TRACE 是否更忠实 | LLM 自解释 | 声明证据一致率 人工忠实度 |
| 动态阈值是否有效 | 固定阈值 | 风险覆盖曲线 选择性准确率 |
| 多样性检索是否减少单源偏差 | 无多样性选择 | 来源覆盖 冲突召回 回答正确性 |
| 反事实补证是否可执行 | 通用改进建议 | 补证成功率 二次回答提升 |
| UI 是否降低过度信任 | 只显示引用 | 错误接受率 核查时间 用户校准度 |

## 7 学术表述边界

- 可以声称：解释与回答共享检索证据，规则轨迹可复算，阈值可审计。
- 不应声称：LLM 内部推理完全可解释。
- 可以声称：系统给出证据质量和不确定性诊断。
- 不应声称：未校准分数是答案为真的概率。
- 可以声称：规则提示关联证据和检索风险。
- 不应声称：规则或引用证明因果关系。
